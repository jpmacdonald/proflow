# ProFlow 1.0 roadmap

ProFlow 1.0 is complete when a reviewed Planning Center plan produces native
presentations and a playlist that satisfy one deterministic semantic contract,
survive independent package read-back, and require human review only for
genuinely ambiguous input or unsupported native behavior.

This roadmap is the authoritative completion checklist. A task is checked only
after its regression tests and the enclosing `just` gate pass.

## 1. Input and tool contracts

- [x] Replace conflicting Planning Center lookahead defaults and bounds with one
  checked `PlanLookaheadDays` contract used by config, MCP, and workflow code.
- [x] Make the high-volume property-test gate run every designated property
  suite at the configured case count.
- [x] Capture each Bible corpus as one immutable, hashed, parsed input used by
  both review reconciliation and rendering.
- [x] Expose the complete v4 project-config JSON Schema through the MCP boundary
  from the same Rust wire types that deserialize the config.
- [x] Pass `just deep`.

## 2. Planned-versus-rendered presentation contract

- [x] Derive one `ExpectedPresentationContract` from every resolved plan.
- [x] Validate final native bytes against required cue shape, macro transitions,
  first-entry background, labels, arrangement traversal, canvas size, and
  nonempty operator traversal.
- [x] Treat a zero-cue presentation as a typed failure unless its presentation
  policy explicitly permits one.
- [x] Return the materialized native evidence in `preview_playlist`; use the same
  report object in preview, receipt, and final build output.
- [x] Add regression cases for song, hymn, doxology, scripture, responsive
  liturgy, nametag, and graphic presentations.
- [x] Pass `just deep`.

## 3. Checked reverse-engineered native core

- [x] Separate safe unchanged reuse from mutation with checked
  `OpaquePresentation`, `EditablePresentation`, and `GeneratedPresentation`
  states.
- [x] Require exact decode/re-encode parity before an existing native document
  may be edited, preventing unknown protobuf fields from being silently lost.
- [x] Resolve cue, group, arrangement, and action references once through a
  canonical `ResolvedPresentationGraph`.
- [x] Retain compact transform capabilities in `LibraryCatalog` so incompatible
  restyles require review during planning rather than failing during execution.
- [x] Prove text fit independently for every field and destination in a
  multi-field cue.
- [x] Keep raw generated protobuf bindings behind an explicitly unstable native
  boundary rather than exposing them as the normal product API.
- [x] Pass `just deep` and the read-only live-library parity audit.

## 4. Package fidelity and release evidence

- [x] Give portable-media discovery, resolution, archive membership, and
  evidence one typed package-plan owner.
- [x] Reopen every staged playlist with the independent package reader and prove
  its document, items, presentations, arrangements, media, and archive order
  match the reviewed package plan.
- [x] Add the six QA-approved contemporary/traditional services from the prior
  three weeks as sanitized semantic end-to-end goldens.
- [x] Record producer version, operating system, export mode, provenance, and
  covered native capabilities for every independent fixture.
- [x] Add a current-version ProPresenter import/save-back release audit and an
  optional thumbnail comparison oracle.
- [ ] Pass `just deep`, corpus parity, and the documented release audit.
  `just deep`, the nine-package Desktop corpus, and the 2,036-presentation safe
  Documents library passed on 2026-07-21. The final checkbox remains open until
  a newly imported playlist is exported back from ProPresenter and compared by
  `just release-audit` as documented in `docs/release-audit.md`.

## 5. Shared native-format library and 1.0 release

- [ ] Define the stable shared crate API around schemas/generated bindings,
  lossless codecs, RTF, native URLs/ZIP handling, package reading, and semantic
  inspection.
- [ ] Keep ProFlow workflow/config/render-policy code and Pew CRDT/sync semantics
  outside the shared crate.
- [ ] Extract the stabilized crate to a separately versioned repository; do not
  introduce a permanent cross-repository path dependency.
- [ ] Migrate ProFlow and Pew to the same released crate in one change per
  consumer, deleting their duplicate protobuf/codecs rather than retaining
  compatibility adapters.
- [ ] Document supported ProPresenter versions and the capability/evidence
  matrix for the shared release.
- [ ] Run `just deep` in ProFlow and Pew's complete verification gate against the
  same crate release.
- [ ] Tag ProFlow 1.0 only after a QA-reviewed real service imports successfully.

## Architecture decision: crate versus repository

A separate crate is required because ProFlow and Pew are separate semantic
products with one native file-format dependency. A separate repository is the
intended final home because the format library needs its own versioning,
compatibility policy, fixture corpus, and release cadence.

Extraction happens after the checked native states and package contract are
stable. Until then, the implementation remains in ProFlow so the boundary can
be corrected without coordinating temporary APIs across two repositories. The
extraction must move existing code and tests; it must not create wrapper layers
or maintain two implementations.

## Explicit non-goals before 1.0

- No Ratatui application; MCP remains the operator boundary.
- No database or second configuration registry.
- No probabilistic LLM decisions inside classification, rendering, or export.
- No new presentation-product features unrelated to completing an existing
  semantic or native-format contract.
- No broad file splitting until the semantic ownership changes above identify
  durable module seams.
